# 图书馆机器人 PID 控距 — 实施计划（git 先行版）

## 一、目标（老师路线图）

机器人按地图导航到 POI 并调整至目标角度 → 拍第一张照片 → YOLO 识别书本最低点（作横杆搜索区的像素上界）→ 以**下方横杆的像素位置为控制量**做 PID 闭环（距离多了向前、少了向后）→ 收敛后拍出"完美照片"（参照 `4_B_097_L_8_1_4.jpg` 构图）。

## 二、双机双 AI 协作机制（git 是地基）

两台电脑各跑一个 ZCode 会话，**按线并行出码**：

| | 线A 感知·数据线 | 线B 控制·真机线 |
|---|---|---|
| 电脑/会话 | 你的电脑（本会话） | 同伴的电脑（另一会话） |
| Owner（拍板人） | 你 | 同伴 |
| 阶段 | S1 标定 + S2 感知评估 | S3 仿真 + S4 上车 + S5 真机试验 |
| 独占文件 | `perception.py`、`utils.py`、`tools/calibrate_target.py`、`tools/eval_perception.py` | `servo.py`、`tools/sim_servo.py`、真机适配层 |
| configs 认领 | `perception` 节 | `control`、`camera` 节 |

**规则（写进 README，两个会话都遵守）：**
1. **契约先行**：S0 由本会话先建 `src/pid_servo/observation.py`（Edge / Observation 数据契约）并提交——这是两线唯一的接缝，之后改动需两人都同意。
2. **文件归属**：各会话只改自己线的文件 + configs 认领节；跨线改动 = 先在人的层面商量。
3. **动手前先 pull，小步勤提交**：两 AI 不直接对话，靠提交历史和 README 对齐。
4. 审验形式不变：每阶段交付"一页纸说明 + 可视化结果 + 要回答的问题"，你们审结果、矫正思路，不审代码。

## 三、已确认的技术决策

- 误差信号：**横杆归一化 y 位置** `err = bar_y/H − target`；书本最低点只做横杆搜索区上界 + 合理性校验
- 感知：不训练新模型——书本最低点用学长已部署 OBB 模型（真机）/ 交付包检测 JSON（离线）；横杆用 OpenCV 剖面法（沿用旧 detect.py，搜索区由书脊底边约束）
- 方向约定：PID 输出正值 = 后退（远离书架），沿用旧项目
- 汇合点：G1/G2 两人一起看图定目标值；G4/G5 两人都到场（一人操作、一人盯车）

## 五、S0 = 先搞 git（批准后立即执行）

在 `图书馆机器人PID控距\` 内：
1. `git init` + 配置 user.name/email（用你们的名字，届时告诉我）
2. `.gitignore`：排除所有数据（`*.jpg`、数据目录、`__pycache__` 等）——**只有代码/配置/文档/实验记录进库，740 张图和 JSON 走本地路径引用**
3. 建骨架：README（分工表+规则）、`configs/default.yaml`、`src/pid_servo/`（契约文件）、`tests/`
4. 首次提交 → **推远程**。远程三选一（需要你定）：
   - **Gitee 私有仓库**（国内快，推荐；需注册）
   - GitHub 私有仓库（有账号就用）
   - 局域网 bare 仓库（一台电脑开共享文件夹当 origin，不出外网）

## 六、实施阶段

- **S1〔线A〕误差标定**：JSON 提取书本最低点 → 横杆检测器 v0 → 740 张 cam_4 跑 `bar_y/H` 分布 + 097/098 落点 → 众数附近挑 3~5 张候选。**G1：Owner 目检定 target/容差**
- **S2〔线A〕感知评估**：检出率、抖动 std、overlay 抽查；验收：097 判"到位"、098 判"需前进"。**G2：两人看图**
- **S3〔线B〕控制移植+仿真**（与 S1/S2 并行）：PID/DistanceServo 换误差源，合成后端改 `frac(d)=A+B/d`，蒙特卡洛对标旧基线 99.1%。**G3：Owner 看报告**
- **S4〔线B〕真机适配层**：Mover（增量式绝对定位）、CameraBackend（只开 cam_4）、RKNN 书脊推理、补光灯；**G4：安全清单逐项确认，两人到场**
- **S5〔线B〕真机单点闭环**：单 POI、低限幅、逐轮留痕、现场调参；**G5：两人到场**，验收 = 收敛且照片与 097 构图相当
- **S6（后续另议）**：接入学长盘点全流程、扩展 cam_3/5

## 七、风险

- 太近横杆出画 → "丢失即后退"退化；OBB 截断帧不稳 → `bar_only` 兜底
- 横杆零点定义偏差 → 目标值标定吸收
- 底盘无速度控制 → dt/settle_ms 真机重定
- 双机并行 → 靠"先 pull、小步提交、文件归属"防冲突；契约改动必须两人同意
- 两人均非深度开发者 → 真机安全权重上调：G4 清单从细，异常即急停

## 八、批准后第一个动作

`git init` → `.gitignore` → 骨架 + 契约文件 → 首次提交 → 问你要远程仓库方式和 git 身份 → 推送 → 启动 S1。
