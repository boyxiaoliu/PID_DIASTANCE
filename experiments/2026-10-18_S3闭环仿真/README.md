# S3 闭环仿真 — 控制器上岗考试

日期：2026-10-18 ｜ 线B（用户 fork 会话承担）｜ 状态：**仿真完成，待用户审验**

## 一句话结论

**两套代码（servo.py 控制器 + shelf_sim.py 合成书架）建成并通过 12,600 次蒙特卡洛考试：
在"检测器逐帧重复性 ≤0.015"的前提下，全部及格线通过（最差格 99.0%，方向性违规 0，
12,600 次仅 1 例浅越线）；设计文档原定的应力噪声档（σ=0.0299）经数学论证对安全线
而言是不可满足的极端压力，按设计如实报告未过 —— 结论是把"单帧重复性实测"列为 S4 上车前的硬性行动项。**

三件套（`docs/01_仿真设计_S3.md` 定稿落地）：

**控制器相对旧项目的改动（全部进 configs，含推导注释）：**

| 改动 | 值 | 起因 |
|---|---|---|
| 饱和态独立小步 `sat_step_m` | 0.20→0.10m | 饱和=看得见但太近；0.10m 一步退回容差带（三档 d* 验算）。丢失（什么都看不见）才用 `backoff_m=0.20` 大步盲退 |
| 饱和连退不计入 `max_backoff` 放弃计数 | — | 标度表只给"丢失"设放弃规则 |
| **近距离前进限幅**（带 3 帧迟滞） | `close_band=0.11`，深档 0.05m / 带内远端 0.15m | 冒烟发现：噪声读数诱发的大步前进一步跨过 d*−0.15m 线（应力档实测深达 0.5m）。推导见 configs `control.loop` 注释 |
| `max_iters` | 12→20 | 远距+噪声下抖动吃预算，失败 94% 是 max_iters 耗尽而非失控 |
| `max_backoff` | 3→5 | d*=1.8 从 0.9m 逃生需连退 4 次，3 次不够（该格收敛率被卡 92%） |
| PID 本体 | 未动 | kp 扫描（见下）证明 3.70 在两场景均为最优，维持不动 |

## 结果总表（7 距离 × 3 噪声 × 3 档 d* × 200 种子 = 12,600 次/场景）

### 场景一"重复性档"（σ₀=0.005，检测器逐帧重复性基准）→ **全部及格线通过**

| 噪声档 | 63 格最低收敛率 | 平均 | 平均轮数 |
|---|---|---|---|
| 1× (σ=0.005) | **99.5%**（线 ≥99%）| 99.9% | 8.1 |
| 2× (σ=0.010) | **99.5%** | 99.9% | 8.1 |
| 3× (σ=0.015) | **99.0%**（线 ≥95%）| 99.7% | 8.3 |

- 方向性违规（饱和/丢失后前进）：**0**（设计硬门）
- 安全线 d ≥ d*−0.15：越线 **1 起** / 12,600（浅，见"安全线分析"）；真机估时 ≈ 40s/POI

### 场景二"应力档"（σ₀=0.0299，设计文档原定值）→ **未过，属预期，原因见下节**

| 噪声档 | 最低收敛率 | 平均 | 越线 |
|---|---|---|---|
| 1× | 93.0% | 97.5% | — |
| 2× | 65.5% | 80.7% | 合计 1755 起 |
| 3× | 44.0% | 59.5% | 方向性违规仍为 **0** |

## 关键发现一：σ=0.0299 不是"测量噪声"，应力档不可作为及格标准

0.0299 来自 247 张**不同构图**照片的 bar_frac 总散布（设计文档亦注明"真值不可测"）。
把它当逐帧测量噪声使用时，换算成距离不确定度：

    σ_d = d*²/B × σ_r = 1.5²/0.68 × 0.0299 ≈ 0.10 m

而容差带 ±0.03（读数）= ±0.10m、安全线余量 0.15m —— **判据带宽和安全线都只有 1~1.5σ**。
数学上：任何"看读数做决策"的反应式控制器，在此噪声下既无法稳定满足中值收敛判据
（应力档失败 96% 是 max_iters 耗尽），也无法保证零越线（悬停在离线 0.05~0.11m 处时，
前进指令约有 50% 概率被 ±0.02m 停稳噪声带过线）。**这不是控制器缺陷，是噪声模型
与判据量纲不匹配。**

佐证：同书架同层分组的组内散布 P50=0.021（`bar_cam4.csv` 25 组 138 张）——组内仍跨
不同拍摄位，说明 0.02~0.04 全部是构图差异，真逐帧重复性只可能远小于此。

**→ S4 硬性行动项：真机上定点（固定距离）连拍 ≥20 帧实测单帧 σ。若 ≤0.015（场景一 3×
档），本实验的"全过"结论直接适用；若实测 >0.02，需先加宽容差带/降采样噪声，再谈闭环。**

## 关键发现二：安全线的可达边界与"迟滞守卫"

安全线 d ≥ d*−0.15 的物理保证链：饱和区（读数出量程）起点距线仅 0.01~0.04m，
守卫必须靠读数门槛，而读数门槛可被噪声致盲。实测事故（应力档 3×）：d=1.13m 处一帧
−2.2σ 噪声把读数打到 0.78 → 守卫失明 + |err| 越过远档阈值 → −0.5m 大步跨到 0.60m。

对策=**前进限幅 + 3 帧迟滞**（近 3 帧任一读数进过守卫带即保持守卫；当前帧掉出带时按
最保守深档 0.05m 限幅）。改善：应力档越线 3371→1755、"已越线又更近"252→31、深跌
0.597→0.630 仅剩首帧即尖峰的无历史长尾。重复性档：越线仅 1 起（12,600 分之一，
浅越线、下一帧饱和回退自愈）。

**残留风险（如实声明）**：起点本身贴近安全线且首帧即大噪声尖峰时，守卫无历史可用。
1×/2× 概率 ≈0；3× 应力档存在。方向性违规（倒向书架的指令）在任何场景均为 0 ——
最坏后果被限定为"多退一步"，无撞架路径。

## 失败样本分析

逐轮轨迹全量在 `*/failures.jsonl`（每行一个样本）。重复性档仅 22/12,600 失败：

- **21 例 max_iters**：集中在 d0=3.0/3.4（9+6 例）——最远起点 + 坏帧/噪声扰动吃掉
  20 轮预算。方向全部正确、止于"没走完"，无安全含义。
- **1 例 lost 放弃**（d*=1.8, d0=0.9, 1×）：从 0.9m 逃生恰用掉 4 次后退配额，第 5 次
  撞上 2.4% 坏帧率触发放弃；末距离 1.94m 距目标仅 0.14m。纯安全侧的可惜 —— S5 真机
  可加"放弃前再观测一次"策略消化。

应力档 2,616 例失败全部为 max_iters（噪声抖动耗预算），与上述数学论证一致。

## 增益扫描（kp，各 21 格 × 200 种子，最坏噪声档）

| kp | 应力档 3× 最低收敛率 | 重复性档 3× 最低收敛率 |
|---|---|---|
| 1.5 / 2.0 | 32.5% / 40.0% | — / 81.5% |
| 2.8 | 50.0% | 87.5% |
| **3.70（维持）** | **50.5%** | **89.0%** |

应力档下 kp 不改变结论（瓶颈是噪声 vs 判据带宽）；重复性档 3.70 最优。
**configs 的 kp=3.70 维持不变，量纲推导值经受住了考试。**

## 仿真证明不了什么（设计 §六，必须与结果同读）

- 不验证感知（153 张真图 + 用户目检闭环已覆盖）；不验证底盘停稳精度、补光、对焦、震动
- σ₀=0.005 是"检测器重复性"的假设基准 —— **S4 定点实测前，"全过"是条件结论**
- 结论单向有效：仿真不过 = 必不过；仿真过了 = 有资格上车（S5 真机是最终关卡）
