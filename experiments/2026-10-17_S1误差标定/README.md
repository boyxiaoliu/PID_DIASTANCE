## 做了什么

1. **书本最低点提取**（S1-1，`tools/extract_spine.py`）
   - 从 740 张交付包的检测 JSON 读 OBB 书脊框（conf≥0.5，取前 20 框），
     底边 y = `cy + (w·|sinθ| + h·|cosθ|)/2`，取最大值；中位长轴偏角 = 帧 roll。
   - 修复：JSON `books` 里混有 `position_ocr` 等 list 型非书条目，按
     "必须含 `yolo11n_obb_detection`" 过滤（有测试锁定）。

2. **横杆检测器 v0 → v0.1**（`src/pid_servo/perception.py`）
   - 剖面取峰（移植旧项目 detect.py）+ 全宽逐列扫描 + 稳健直线拟合。
   - 搜索区上界 = 书本最低点 + 1%H（"书本最低点作像素上界"的落地）。
   - **升级**：fitLine(HUBER) → RANSAC（`_ransac_line`，固定种子）。
     起因：横杆下方沿宽度方向混有 横杆顶边 / 标签牌底边 / 立柱断口，
     HUBER 被少数派边拉偏（097 内点率仅 45%），RANSAC 锁主导边。

3. **全量跑批 + 体检**（`tools/calibrate_target.py`，阈值见 configs `health:`）

## 关键发现（体检拼图 `runs/s1_bar/pick_exp/bottom_layouts.png`）

横杆搜索带内**不是一条贯穿全宽的直线**，随构图远近呈不同结构：

- 近拍（spine≈0.99）：灰色横杆带全宽可见，结构干净（094_R_6_2 那类）
- 中距：横杆 + 标签牌（牌位随 POI 列位变化，无固定 x）
- 远拍：搜索带内出现**斜的搁板沿/大块暗区**（如 100_R_8_1，f=0.912 疑似锁到斜边）
- 立柱在部分 POI 挡住横杆左端（5/27 窗口无峰）

## G1 用户目检结论（2026-10-18 补）

- ✅ **蓝线（书本最低点）人检 ≥90% 正确** → S1-1 提取质量验收通过
- ⚠️ **用户发现"黄蓝重合"态**：多数图黄线=横杆下沿、蓝线=上沿（横杆带上下边界）；
  下沿出画时黄线跳到上沿、与蓝线重合 → 读数突变且物理含义="太近"。
  数据证实：幸存 168 中 15 张间距<0.015（干净群间距中位 0.058）。
- **对策**：新增体检规则 `health.gap_min_frac=0.015`，重合态剔除
  （幸存 168→153）；**闭环安全规则（S3 落实）：此状态=太近，只许后退**。
  不改锁定边（下沿群 153 张分布干净、量程够用），缺陷用规则兜住。

## 结论与遗留

- ✅ 信号方向性在样例对上成立；roll 体检阈值 3° 定案
- ✅ RANSAC 优于 HUBER（幸存 +14，主导边锁定符合预期）
- ⚠️ **未定**：bar_frac 分布混有多种物理结构（横杆带 vs 斜搁板沿），
