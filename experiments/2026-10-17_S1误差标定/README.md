## 做了什么

1. **书本最低点提取**（S1-1，`tools/extract_spine.py`）
   - 从 740 张交付包的检测 JSON 读 OBB 书脊框（conf≥0.5，取前 20 框），
     底边 y = `cy + (w·|sinθ| + h·|cosθ|)/2`，取最大值；中位长轴偏角 = 帧 roll。
   - 修复：JSON `books` 里混有 `position_ocr` 等 list 型非书条目，按
     "必须含 `yolo11n_obb_detection`" 过滤（有测试锁定）。

2. **横杆检测器 v0 → v0.1**（`src/pid_servo/perception.py`）
   - 剖面取峰（移植旧项目 detect.py）+ 全宽逐列扫描 + 稳健直线拟合。
   - 搜索区上界 = 书本最低点 + 1%H（"书本最低点作像素上界"的落地）。
   - **升级**：fitLine(HUBER) → RANSAC（`_ransac_line`，固定种子）。
     起因：横杆下方沿宽度方向混有 横杆顶边 / 标签牌底边 / 立柱断口，
     HUBER 被少数派边拉偏（097 内点率仅 45%），RANSAC 锁主导边。

3. **全量跑批 + 体检**（`tools/calibrate_target.py`，阈值见 configs `health:`）

## OpenCV 替代方案普查（2026-10-18，用户发起探索）

**候选实测**（4 张难图 + 全量 247 张基准，对比图 `runs/s1_bar/pick_exp/methods_compare.png`）：
- **HoughLinesP+Canny：出局**——096 图上锁到书本底边（斜线），边缘源太粗
- **LSD（cv2 5.0 自带）+ 现行 RANSAC 融合：有真价值但有代价**
  - 与现行一致 94/121（中位差 5.7px）；收复现行拒收图 36 张 + 未检出 4 张
  - 代价1：27/121 不一致（部分是假阳性，如把"下一层书顶"当横杆——089_R_9_2 目检实锤）
  - 代价2：182ms/帧（4 倍慢，仍可用）
  - 代价3：采用则读数总体改变 → target 需重标定、用户需重目检

**结论（暂定）**：现行方案已端到端验证（153 张+用户目检），被拒帧在闭环中有
"丢失→后退重试"兜底，收复帧改善的是效率不是正确性。**维持现行，LSD 列为
S6 扩展 cam_3/5 时的候选升级**。若采用需：27 不一致 + 40 收复帧全部目检、
重标定 target、重出评审页。

## G1 新增约束：画面内黄蓝两线不相交（2026-10-18，用户提出）

- **物理不变量**：横杆下沿恒在书底之下 → 黄线（拟合直线）与蓝线（书底水平线）
  在画面内 [0,W] 任一位置都不得相交。比"中点间距"更严：斜率歪到边角越线也拦截。
- **实现**：`perception.yellow_crosses_blue()`（检查黄线在画面左右两端的较低端
  是否 ≤ 书底）；四处生效 = perception.observe（闭环自动作废→按丢失后退）、
  calibrate_target 体检、两个导出工具。
- **数据**：拦下 13 张（10 张原饱和群、3 张原有效群），幸存 153→150；
  干净组中位 0.9546，target=0.955 不变。39 项测试全绿。
